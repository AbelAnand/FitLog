# SplitLog on Android

The same app as the iPhone version, in a native Capacitor shell under `android/`. The promises are
the same: everything stays on the device, there is no account, no server, no network request, no
analytics and no crash reporting. The application id `com.abelanand.fitlog` keeps the old name,
like the iOS bundle id; only what users read says SplitLog.

## What is in `android/`

| Piece | File | Notes |
|---|---|---|
| Activity | `app/src/main/java/com/abelanand/fitlog/MainActivity.kt` | Registers the three in-app plugins. Debuggable builds honour the `FITLOG_ROUTE` / `FITLOG_JS` intent extras (same hooks as the iOS test build). |
| Storage | `LocalStorePlugin.kt` | SQLite at `files/FitLog/fitlog.sqlite` (WAL, `synchronous = FULL`, one transaction per batch, `records(tbl, id, json)`), the same shape as `ios/App/App/LocalStorePlugin.swift`, so `src/db/persistence.ts` is unchanged and every record still goes through `src/db/clean.ts`. Included in Auto Backup and device transfer (`res/xml/backup_rules.xml`, `data_extraction_rules.xml`). |
| Widget data | `WidgetBridgePlugin.kt` | Stores the `widgetData` JSON in SharedPreferences. There is no home-screen widget yet (see the end of this file). |
| Back | `BackGesturePlugin.kt` + `src/lib/android-back.ts` | The system back gesture/button closes an open sheet, presses the workout editor's own Back (which asks Save or Discard when there are unsaved changes), and backgrounds the app from a root tab. |
| System bars | `src/lib/android-bars.ts`, `SystemBars` in `capacitor.config.ts` | Edge to edge, with `env(safe-area-inset-*)` carrying the real bar heights on WebView 140+, so the iPhone CSS works unchanged. Bar icon colour follows the theme. |
| Icons | `res/mipmap-*` | Generated by `@capacitor/assets` from `docs/app-store/icon-1024.png` (adaptive icon on the dark background). Regenerate with the recipe below. |
| Share | `src/lib/share-android.ts` | A backup or CSV is written to `cache/shared/` and handed to the share sheet through the `FileProvider` (`res/xml/file_paths.xml`) as a content URI. Android reports the share done as soon as an app is chosen, so the file stays until the next share instead of being deleted at once as on iOS. **Not wired yet**: `shareTextFile` in `src/lib/csv.ts` needs `if (isAndroid) return shareTextFileAndroid(filename, text)` at the top (see "Not yet done"). Until then the share sheet still works, but the file is deleted as soon as an app is chosen, which can fail an upload that reads it late. |
| Reminders | `src/lib/notifications.ts` | Inexact alarms (`isExactNotification: false`), so `SCHEDULE_EXACT_ALARM` is removed from the manifest and the "Alarms & reminders" prompt never appears. `POST_NOTIFICATIONS` is requested only from the Settings toggles. |

## Build and run (debug)

Prerequisites: Android Studio (for its SDK and bundled JDK), an emulator or a phone with USB
debugging. The system Java on this Mac is newer than Gradle accepts, so point `JAVA_HOME` at
Android Studio's JDK for every Gradle command.

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_SDK="$HOME/Library/Android/sdk"
echo "sdk.dir=$ANDROID_SDK" > android/local.properties   # git-ignored

npm install
CAP_BUILD=1 npx vite build && npx cap sync android         # web bundle into android/app/src/main/assets/public
(cd android && ./gradlew assembleDebug)                     # android/app/build/outputs/apk/debug/app-debug.apk

$ANDROID_SDK/emulator/emulator -list-avds
$ANDROID_SDK/emulator/emulator -avd Pixel_9 &               # or plug in a phone
$ANDROID_SDK/platform-tools/adb install -r android/app/build/outputs/apk/debug/app-debug.apk
$ANDROID_SDK/platform-tools/adb shell am start -n com.abelanand.fitlog/.MainActivity
```

Installing over an earlier build keeps the log. Uninstalling deletes it (Android's backup may
restore it on reinstall if the device has backup turned on, but do not rely on that: save a
backup file first).

### Checking the stored data on an emulator or a debug build

```bash
adb exec-out run-as com.abelanand.fitlog cat files/FitLog/fitlog.sqlite > /tmp/fitlog.sqlite
sqlite3 /tmp/fitlog.sqlite "select tbl, count(*) from records group by tbl"
```

(`run-as` works for debuggable builds only. In WAL mode the `-wal` file may hold the latest
writes until a checkpoint; copy `fitlog.sqlite-wal` alongside it, or force-stop the app first.)

### Driving a debug build (same hooks as the iOS simulator build)

```bash
CAP_BUILD=1 npx vite build --mode simtest && npx cap sync android && (cd android && ./gradlew assembleDebug)
adb shell am start -n com.abelanand.fitlog/.MainActivity --es FITLOG_ROUTE /progress \
  --es FITLOG_JS 'window.__fitlog.seedDemo()'
adb exec-out screencap -p > screen.png
```

`simtest` bundles contain `src/db/devtools.ts` (`window.__fitlog`). **Never ship one**: build
with `CAP_BUILD=1 npx vite build` (no `--mode`) before `bundleRelease`.

### Regenerating the launcher icons

```bash
mkdir -p assets-android-tmp
# icon-only.png: docs/app-store/icon-1024.png as it is (legacy icon)
# icon-background.png: 1024×1024 solid #0b0d10
# icon-foreground.png: the artwork at 84 % on #0b0d10, so no launcher mask clips the bars
# splash.png / splash-dark.png: assets/splash.png and assets/splash-dark.png
npx capacitor-assets generate --android --assetPath assets-android-tmp \
  --iconBackgroundColor '#0b0d10' --iconBackgroundColorDark '#0b0d10' \
  --splashBackgroundColor '#0b0d10' --splashBackgroundColorDark '#0b0d10'
rm -rf assets-android-tmp
```

## Signed release

### 1. Make a keystore (once, keep it forever)

```bash
keytool -genkeypair -v -keystore ~/Keys/splitlog-upload.jks -alias splitlog \
  -keyalg RSA -keysize 2048 -validity 10000
```

Store the file and both passwords in a password manager and in a second place. Losing it means
losing the ability to update the app (Play App Signing keeps the *app* signing key on Google's
side, but the *upload* key is yours, and resetting it is a support request).

### 2. Point the build at it (git-ignored)

`android/keystore.properties`:

```properties
storeFile=/Users/you/Keys/splitlog-upload.jks
storePassword=…
keyAlias=splitlog
keyPassword=…
```

`android/app/build.gradle` reads this file if it exists and signs the `release` build type with it.
`android/.gitignore` ignores `keystore.properties`, `*.jks` and `*.keystore`.

### 3. Build the bundle

```bash
npm test
CAP_BUILD=1 npx vite build && npx cap sync android
(cd android && ./gradlew bundleRelease)
# android/app/build/outputs/bundle/release/app-release.aab
```

Raise `versionCode` in `android/app/build.gradle` for every upload (and keep `versionName` in step
with the iOS `MARKETING_VERSION`). Release builds have no `FITLOG_*` test hooks: they are gated on
the debuggable flag.

An APK for sideloading: `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`.

### Target SDK

`targetSdkVersion = 36` (Android 16), `compileSdkVersion = 36`, `minSdkVersion = 24` (Android 7.0,
the oldest Capacitor 8 supports). Google Play requires new apps and updates to target the previous
year's API level or later; 36 covers submissions through 2027. Targeting 35+ makes the app
edge-to-edge, which Capacitor's `SystemBars` plugin and the existing safe-area CSS handle.

### Data safety form

| Question | Answer |
|---|---|
| Does your app collect or share any of the required user data types? | **No** |
| Is all of the user data collected by your app encrypted in transit? | Not applicable: nothing is transmitted. The app has no INTERNET permission. |
| Do you provide a way for users to request that their data is deleted? | Not applicable to collected data (none). In-app, Settings → Erase everything removes the log from the phone. |
| Does your app use any data for advertising, analytics, or tracking? | No |

Rationale that matches the manifest: no `INTERNET` permission, no Play Services or Firebase
dependency, no SDK that phones home. The reminders are local notifications. Backup files are
written to the app's cache and handed to the system share sheet; where they go is the user's
choice. The Android system backup (`allowBackup`) copies the app's private files to the user's own
Google account backup, which Google's form does not count as collection by the developer.

### Permissions in the final manifest

Merged from the app and the Capacitor plugins it uses:

| Permission | Why | Prompt |
|---|---|---|
| `POST_NOTIFICATIONS` | Reminders (Android 13+) | Runtime, only when a reminder is switched on in Settings |
| `RECEIVE_BOOT_COMPLETED` | Re-arm scheduled reminders after a restart (local-notifications plugin) | None |
| `WAKE_LOCK` | Deliver a scheduled reminder while the screen is off (local-notifications plugin) | None |
| `VIBRATE` | Haptics plugin (taps, PR celebration) | None |

Removed on purpose: `INTERNET` (the bundle is served from assets; the web view never loads from
the network) and `SCHEDULE_EXACT_ALARM` (reminders are inexact). Check the merged manifest after
adding a plugin:

```bash
$ANDROID_SDK/build-tools/36.0.0/aapt2 dump permissions android/app/build/outputs/apk/debug/app-debug.apk
```

## Verified on the emulator (2026-10-09, Pixel 7 AVD, Android 16 / API 36, WebView 139)

Debug build, driven through the `FITLOG_ROUTE` / `FITLOG_JS` hooks and `adb shell input`:

- Launches with no `INTERNET` permission; the bundle loads from assets (`https://localhost` is
  intercepted by Capacitor). No permission prompt at launch.
- A workout with three sets entered through the UI, then force-stop and relaunch: the log is
  there. The SQLite file pulled with `run-as` is in WAL mode and holds 1 workout, 1 exercise,
  1 workout_exercise, 3 sets.
- Back gesture: live workout → Home; Home → launcher (app backgrounded, restored on relaunch);
  finished workout with an unsaved edit → "Save your changes?"; back again closes it; Discard
  returns Home with the set unchanged.
- Save a backup: the share sheet opens with `fitlog-backup-<date>.json`; dismissing it reports
  `cancelled` (no "Backup saved" toast).
- Restore: Choose file opens the system picker; a `.json` is selectable; the preview sheet shows
  the counts; Restore imports 33 workouts and 495 sets.
- Reminders: turning on Daily check-in shows the notification permission prompt; after Allow, 14
  inexact `RTC_WAKEUP` alarms with a one-hour window are registered, with no "Alarms & reminders"
  settings screen.
- Privacy policy opens Chrome.

Layout: this AVD's WebView (139) is below the 140 Capacitor needs for real `env(safe-area-inset-*)`
values, so Capacitor pads the web view instead (insets read 0, viewport 411×838 of 412×915) and
the bars sit on the window's dark background. On a device with a current WebView (Pixel 9 AVD has
142 after a Play update) the web view goes under the bars and the iPhone backdrop CSS applies.
Both look right; the second has not been screenshotted because that AVD had no free space.

## Not yet done

- **Home-screen widget.** `WidgetBridgePlugin` stores the streak snapshot; an `AppWidgetProvider`
  (RemoteViews) that reads `widgetData` from the `widget` SharedPreferences, plus a
  `fitlog://start` tap target, is the remaining piece. The iOS widget's layout is in
  `ios/FitLogWidget/`.
- **Share path in `src/lib/csv.ts`** (owned by another change at the time of writing): add
  `import { shareTextFileAndroid } from './share-android'`, import `isAndroid` from `./native`,
  and put `if (isAndroid) return shareTextFileAndroid(filename, text)` as the first line of
  `shareTextFile`. Without it, the cache copy is deleted the moment an app is chosen.
- **Wording that says "iPhone"** in screens the Android build shares with iOS
  (`src/App.tsx`, `src/pages/Home.tsx`, `src/pages/Settings.tsx`, `src/data/limits.ts`). The
  orchestrator's report lists each spot; `isAndroid` / `isIOS` from `src/lib/native.ts` are ready
  for it. Until then Android users read "this iPhone" in a few hints.
- **Testing on a real phone.** The emulator covers storage, the back gesture, the share sheet
  and the file picker, but not haptics, notification delivery after a reboot, Doze behaviour of
  inexact reminders, or OEM keyboards. Run the phone checklist from `docs/app-store/README.md`
  section 6, minus the widget steps.
- **Play Console assets**: feature graphic, the IARC questionnaire, and a Google Play developer
  account (one-time fee; new personal accounts must run a closed test with 12 testers for 14 days
  before production access).
- **Predictive back animation** (`android:enableOnBackInvokedCallback`): off, which is Capacitor's
  default; turning it on is cosmetic.
