# SplitLog (repo FitLog) — notes for Claude

- **Name:** the product is SplitLog since 2026-10-06. The repository, the Pages address, the bundle id `com.abelanand.fitlog`, the `fitlog://` scheme, the storage folder and the backup file marker `app: "FitLog"` deliberately keep the old name; only what users read changed.

- Free workout tracker for iPhone, a **native Capacitor app** (`ios/`, bundle id `com.abelanand.fitlog`, signing team Q4X5P825Z6), heading for the App Store. Made by Abel, who also uses it daily, so his log is real data.
- **Everything is stored on the device. There is no server, no account, and the app makes no network requests.** Do not add any without Abel deciding to: "Data Not Collected" is the product's promise and its App Store privacy label.
- Storage: `src/db/`. `LocalDb` (db.ts) holds the whole log in memory and mirrors it to a `Persistence`. On iPhone that is `LocalStorePlugin.swift`, a SQLite file at `Library/Application Support/FitLog/fitlog.sqlite` (records of table, id, JSON; WAL; every batch is one transaction). In a browser (`npm run dev`) it is localStorage. In tests it is `memoryPersistence`. The file must stay inside backups: never mark it excluded, never move it to Caches.
- Every record entering the database goes through `src/db/clean.ts`, whether from storage, the app, or a restored file. Restored files are untrusted input. Size limits live in `src/data/limits.ts`; inputs use the same numbers.
- Backup and restore: `src/db/backup.ts`. The backup is JSON (`format: 1`); restoring merges by id and removes nothing. A workout already on the device under another id with identical sets is recognised by signature (`planImport` in db.ts): a backup replaces it with its fuller copy, a spreadsheet leaves it alone. The CSV export can also be restored, with ids derived from content so a second import changes nothing. If the stored shape changes, bump `format`, keep reading the old one, and add a test with an old file.
- Reads and writes for screens: `src/api/queries.ts` and `src/api/mutations.ts` (TanStack Query on top of `db`). A change is applied to the cache first (pure transforms in `src/api/optimistic.ts`), then saved through a per-workout ordered queue (`src/api/queue.ts`). Row ids are made on the device (`src/lib/uuid.ts`). Do not use TanStack's `scope` for ordering: it refuses to advance while the app is not focused. Failures surface through the global toast (`MutationCache.onError` in App.tsx); set `meta.error` on new mutations.
- Explicit Save (Abel asked for it): a live session saves every change as it is made, but a finished workout or a plan opens for editing. Its writes are held in `src/api/hold.ts` (the on-screen change still happens), the header shows Save, and leaving asks Save or Discard. `saveHeld` runs the writes in order; `discardHeld` re-reads from the database. While there are unsaved changes the native swipe-back gesture is off (`BackGesturePlugin.swift`, `setBackGesture`).
- All progression/PR/streak math is computed from `useAllSets()` (`src/lib/prs.ts`, `src/lib/streak.ts`). Weights are stored as entered + unit; convert with `src/lib/units.ts`.
- Build: `npm run build:ios` (`tsc -b`, Vite with base `/`, then `cap sync ios`). `npm run build` is the same bundle without the sync and is what CI runs. `npm test` is vitest over the pure logic, the database, and backup/restore. Keep `tsc -b` and `oxlint` free of errors.
- The public site is `site/` (overview, guide, privacy, support), plain HTML published to https://abelanand.github.io/FitLog/ by `.github/workflows/deploy.yml`. It is not the app. Keep `site/privacy.html` and `site/guide.html` true whenever data handling or features change. `site/sw.js` removes the service worker of the old web app; leave it in place.
- Native-only behaviour is gated on `isNative` from `src/lib/native.ts` (status bar, keyboard, haptics, share sheet). Files are handed to the user with `shareTextFile` in `src/lib/csv.ts`.
- To verify without a phone: `CAP_BUILD=1 npx vite build --mode simtest && npx cap sync ios`, then `xcodebuild -project ios/App/App.xcodeproj -scheme App -destination 'platform=iOS Simulator,id=<sim id>' -derivedDataPath ios/DerivedData build CODE_SIGNING_ALLOWED=NO`, then `xcrun simctl install/launch/io screenshot`. `simtest` builds (and dev) load `src/db/devtools.ts`, which puts `window.__fitlog` on the page: `seedDemo()`, `restoreFromDocuments(name)`, `show(text)`. Drive it with `SIMCTL_CHILD_FITLOG_ROUTE=/progress` and `SIMCTL_CHILD_FITLOG_JS='…'` on `simctl launch` (debug builds only). The iOS 18.6 runtime works; the 26.5 simulator's web view had problems on this Mac. **Never archive a simtest bundle; run `npm run build:ios` first.**
- The iOS project uses Swift Package Manager (no CocoaPods). The root controller is `FitLogViewController` (set in `SceneDelegate.swift`, not the storyboard); it registers the in-app plugins `WidgetBridgePlugin` and `LocalStorePlugin`. New Swift files must be added to `project.pbxproj` by hand (file reference, build file, group, Sources phase). The widget target `FitLogWidget` reads `widgetData` JSON from the `group.com.abelanand.fitlog` app group.
- Design tokens are in `src/styles/app.css` under `@theme`. Restyle by changing tokens and the primitives in `src/components/ui.tsx`, not by scattering colors. Base element resets must stay inside `@layer base` or they override Tailwind utilities.
- Keyboard and taps (src/main.tsx): a press on a control must not blur the focused field until the click has been delivered, because dismissing the keyboard resizes the web view and the tap lands elsewhere. `SwipeRow` clips its overflow, so nothing may hang outside a row: the PR badge is a corner tab inside the weight field (`PrBadge`, which needs a `@container` parent and goes crown-only when the number is long). Tab screens scroll under a fixed status-bar backdrop (`TabLayout`).
- Motion (Abel asked for it, and for it to be light on the phone): the rules are in the Motion section of `src/styles/app.css` and enforced by `src/__tests__/motion.test.ts`: keyframes animate only `transform` and `opacity`, nothing loops, nothing exceeds about half a second, no `will-change`, and every class is listed under `prefers-reduced-motion`. Controls use `.press` / `.press-soft`; screens use `page-push` / `page-fade` / `page-back` chosen by navigation type; items added after a screen has loaded ease in and removed ones close up first (`src/lib/motion.ts`). Sheets render through a portal to `document.body` so an animating screen cannot drag them. No animation libraries.
- Reminders use `@capacitor/local-notifications` (`src/lib/notifications.ts`): daily check-in ids 1001-1014 rescheduled from Home, gym nudges ids 2001-2010 started from the start sheet or editor menu. Their settings and the theme live in Capacitor Preferences, not the database, so they are not part of a backup file.
- Sessions: `paused_at` + `paused_seconds` on workouts; `activeSeconds()` in `src/lib/duration.ts` is the single source of truth for elapsed time. Plans are workouts with `is_plan = true`; they are excluded from `allSets`, streaks, and "last session" hints. Exercise check-off is `completed_at` on the workout's exercise entry.
- Drop sets: `set_type = 'drop'` plus `drops` `[{weight, reps}]` in the parent set's unit; volume includes drops, PRs use the top weight only.
- Cardio variables: an exercise's `metrics` (ordered keys from `src/data/cardio-metrics.ts`, max 4) drive the cardio card columns, quick fill, totals, and the last-time line. time/distance/incline are fields on the set; the rest live in `extra`. Distance is derived from speed × time when only those are logged (`cardioKm`).
- Gestures: `Sheet` (ui.tsx) drags down to dismiss (CSS keyframes animate in/out; never rely on requestAnimationFrame, hidden tabs stall it). `SwipeRow` gives iOS swipe-to-delete.
- `supabase/` and `scripts/export-from-server.mjs` are legacy: the online version's schema, and the way to bring an account's data out of it. The app does not use them. Do not pause, delete or modify the Supabase project without Abel saying his data is safely in the app.
- Submission material is in `docs/app-store/`.
